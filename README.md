# Консоль VirtualBox для Codex

Плагин `virtualbox` позволяет Codex работать с виртуальными машинами Oracle VirtualBox на вашем Windows-компьютере. Например, можно попросить проверить свободное место в Debian, получить вывод команды и посмотреть, что сейчас на экране ВМ. Для связи с гостем используется локальный `VBoxManage`. IP-адрес, SSH и проброс портов для этого не нужны.

| Задача | Как работает | Что нужно в гостевой системе |
| --- | --- | --- |
| Узнать имена и состояние ВМ | Читает список зарегистрированных машин | ВМ может быть выключена |
| Посмотреть экран | Сохраняет PNG первого виртуального монитора | Запущенная ВМ |
| Выполнить сценарий и прочитать вывод | Guest Control запускает отдельный процесс и возвращает `stdout` и `stderr` | Работающие Guest Additions, гостевая учётная запись и Bash или Windows PowerShell |
| Ввести команду в видимый терминал | Печатает строку, снимает экран для сверки и отдельно отправляет Enter | Активный терминал и раскладка English (US). Подходит в том числе для консоли RouterOS |

## 1. Подготовить другой компьютер

Установите Codex, Git, Python 3.10 или новее и Oracle VirtualBox **на том Windows-компьютере, где будут работать ВМ**. Войдите в Codex под своим аккаунтом. Зарегистрируйте или импортируйте нужную машину в VirtualBox Manager. Если ВМ остаётся на другом хосте, установка плагина на ваш ноутбук сама по себе не создаёт удалённое соединение.

**Хост Windows — PowerShell.** Проверьте, что команды доступны:

```powershell
codex --version
codex plugin --help
git --version
python --version
```

В справке Codex должны быть команды `add`, `list` и `marketplace`. Если установленная сборка их не показывает, обновите Codex. Для Python достаточно стандартной библиотеки. [Codex CLI](https://developers.openai.com/codex/cli/) · [Git для Windows](https://git-scm.com/downloads/win) · [Python для Windows](https://www.python.org/downloads/windows/) · [Oracle VirtualBox](https://www.virtualbox.org/wiki/Downloads)

## 2. Установить плагин из GitHub

**Хост Windows — PowerShell.** Зарегистрируйте этот репозиторий как источник плагинов и установите `virtualbox`:

```powershell
codex plugin marketplace add https://github.com/matvejchukhanov-ops/virtualbox.git --ref main
codex plugin add virtualbox@local-vm-tools
codex plugin list --marketplace local-vm-tools --json
```

Успешная установка отображается в массиве `installed`. У записи `virtualbox@local-vm-tools` должны быть `installed: true` и `enabled: true`.

**В новом чате Codex** отправьте:

> Используй $virtualbox:console. Покажи зарегистрированные ВМ и отметь, какие сейчас запущены.

Сверьте имена с VirtualBox Manager. Если машин несколько, указывайте точное имя нужной ВМ в последующих запросах.

<details>

Скачайте репозиторий через **Code → Download ZIP** и распакуйте его в постоянную папку. Откройте PowerShell **на хосте Windows** в каталоге, где лежат этот README и папка `.agents`. Для этого варианта выполните:

codex plugin add virtualbox@local-vm-tools

Codex использует этот путь как источник. Оставьте распакованный каталог на месте для повторной установки и обновлений.

## 3. Подключить гостевую систему

Запустите нужную ВМ в VirtualBox Manager. В чате Codex попросите показать её состояние и версию Guest Additions. Для Guest Control ожидаются `state = running` и `additions_level` от `2`. Для снимка экрана достаточно `running`.

Если дополнения ещё не установлены, в **окне работающей ВМ** откройте меню **Устройства → Подключить образ диска Дополнений гостевой ОС**. В гостевой Windows запустите `VBoxWindowsAdditions.exe` с подключённого диска. В гостевом Linux выберите инструкцию для своего дистрибутива: набор пакетов для сборки модулей зависит от ядра. При необходимости перезагрузите ВМ, затем снова проверьте `additions_level`. Oracle рекомендует использовать версию дополнений, соответствующую версии VirtualBox на хосте. [Установка Guest Additions в Linux и Windows](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/guestadditions.html)

Узнайте имя **гостевой** учётной записи. Внутри **Linux — Bash** выполните `id -un`. Внутри **Windows — PowerShell** выполните `$env:USERNAME`. Это имя потребуется для запуска команд. Регистр букв в имени пользователя Linux имеет значение.

## 4. Проверить выполнение команды

В примере ниже замените `ИМЯ_ВМ` и `ИМЯ_ПОЛЬЗОВАТЕЛЯ` своими значениями. **В чате Codex**, для гостевой Linux:

> Используй $virtualbox:console. Через Guest Control на ВМ «ИМЯ_ВМ» от имени «ИМЯ_ПОЛЬЗОВАТЕЛЯ» выполни hostname и id -un. Покажи текстовый вывод.

Для **гостевой Windows** замените команды на `hostname` и `whoami` и попросите использовать PowerShell. На хосте появится системное окно Windows. Введите в нём пароль пользователя ВМ. Для разовой проверки достаточно нажать ОК. В результате должны появиться имя гостевого узла и имя пользователя. Терминал гостя можно держать закрытым.

**Чтобы вход работал в следующих чатах**, попросите Codex выполнить такую же проверку и сохранить вход на этом ПК с `--remember`. После успешной команды результат должен содержать `credential_saved: true`. Повторите обычный запрос с тем же именем пользователя. Теперь вывод должен прийти без запроса пароля.

Запись хранится в Диспетчере учётных данных текущего пользователя Windows и привязана к UUID машины и имени гостевого пользователя. При установке на другой компьютер, смене профиля Windows или клонировании ВМ с новым UUID пройдите первый вход снова. Пароль вводится только в локальное окно.

## Если у ВМ нет Guest Additions

Войдите в гостевую систему, откройте терминал, выберите English (US) и поставьте курсор на пустую строку приглашения. **В чате Codex** для Linux можно попросить:

> Используй $virtualbox:console. Посмотри на экран ВМ «ИМЯ_ВМ». Введи hostname, сверь набранную строку на снимке, затем нажми Enter и прочитай имя узла.

Для RouterOS пример команды — `/system identity print`. Режим клавиатуры поддерживает одну строку печатного ASCII длиной до 1 024 символов. Для кириллицы, многострочных сценариев и отдельного потока ошибок используйте Guest Control.

## Диагностика

| Что произошло | Что проверить |
| --- | --- |
| Codex показывает пустой список ВМ | Откройте VirtualBox Manager под тем же пользователем Windows и проверьте, что ВМ зарегистрирована. |
| Плагин не находит `VBoxManage.exe` | Проверьте установку Oracle VirtualBox на хосте. Плагин проверяет каталоги установки и `PATH`. |
| Guest Additions не сообщают о готовности | Дождитесь загрузки гостя и снова запросите состояние. Если уровень остаётся ниже 2, проверьте службу `VBoxService` внутри ВМ. |
| `VERR_AUTHENTICATION_FAILURE` | Сверьте гостевое имя, регистр и раскладку в окне Windows. Проверьте вход этим пользователем внутри ВМ. После смены пароля используйте `--remember` с новой учётной информацией. |
| Команда напечаталась с другими символами | До нажатия Enter проверьте фокус терминала, раскладку и строку на свежем снимке. |
| Команда завершилась ошибкой | Попросите Codex показать `stdout`, `stderr` и `vbox_exit`. Последнее поле — код утилиты VBoxManage. По умолчанию плагин даёт гостевой команде 30 секунд. |

## Обновление и удаление

**Хост Windows — PowerShell.** Для установки из GitHub:

```powershell
codex plugin marketplace upgrade local-vm-tools
codex plugin add virtualbox@local-vm-tools
codex plugin list --marketplace local-vm-tools --json
```

Для локального источника обновите файлы в исходной папке, затем повторите `codex plugin add virtualbox@local-vm-tools`.

Чтобы удалить плагин и его источник, **на хосте Windows в PowerShell** выполните:

```powershell
codex plugin remove virtualbox@local-vm-tools
codex plugin marketplace remove local-vm-tools
```

Чтобы отозвать также сохранённый вход, откройте **Панель управления → Диспетчер учётных данных → Учётные данные Windows** и удалите запись `Codex.VirtualBox/` с UUID нужной ВМ. UUID доступен в сведениях о машине.

## Проверенная конфигурация

Версия плагина **1.1.0** проверена на хосте Windows с VirtualBox **7.2.16** и гостевой Debian 13. Выполнены чтение экрана, ввод строки с проверкой перед Enter, запуск Bash без открытого терминала и повторный вход по сохранённой записи. Вывод с кириллицей получен отдельно в `stdout` и `stderr`. Сквозная проверка Guest Control с гостевой Windows и проверка консоли RouterOS остаются открытыми.
